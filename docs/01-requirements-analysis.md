# Kafka & 微服务 Testcontainers 白盒测试需求分析文档

## 1. 项目背景

### 1.1 项目概述

本项目旨在建立一套基于 **Testcontainers** 的白盒测试框架，用于对 Kafka 消息中间件及相关微服务进行全面的集成测试。通过容器化的测试环境，确保测试的可重复性、隔离性和真实性。

### 1.2 术语定义

| 术语 | 定义 |
|------|------|
| **Testcontainers** | 一个支持 JUnit 测试的 Java 库，提供轻量级、一次性的 Docker 容器实例 |
| **白盒测试** | 基于代码内部结构和逻辑的测试方法，测试者需要了解程序内部工作机制 |
| **Kafka** | Apache Kafka，分布式流处理平台，用于构建实时数据管道和流应用程序 |
| **微服务** | 一种架构风格，将应用程序构建为一组小型、自治服务的集合 |

## 3. 测试场景分析

### 3.1 Kafka 核心测试场景

```
┌─────────────────────────────────────────────────────────────────┐
│                    Kafka 测试场景矩阵                           │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌─────────────┐    ┌─────────────┐    ┌─────────────┐         │
│  │  Producer   │───▶│    Kafka    │───▶│  Consumer   │         │
│  │   测试      │    │   Broker    │    │   测试      │         │
│  └─────────────┘    └─────────────┘    └─────────────┘         │
│        │                  │                  │                  │
│        ▼                  ▼                  ▼                  │
│  ┌───────────────────────────────────────────────────┐         │
│  │  测试维度：                                        │         │
│  │  • 消息发送确认（acks=0/1/all）                   │         │
│  │  • 消息格式（JSON/Avro/Protobuf）                 │         │
│  │  • 分区策略（轮询/Key Hash/自定义）               │         │
│  │  • 消费模式（at-least-once/at-most-once/exactly-once）│     │
│  │  • 错误处理（重试/死信队列）                       │         │
│  └───────────────────────────────────────────────────┘         │
└─────────────────────────────────────────────────────────────────┘
```

### 3.2 微服务集成测试场景

```
┌─────────────────────────────────────────────────────────────────┐
│                  微服务集成测试场景                              │
├─────────────────────────────────────────────────────────────────┤
│                                                                 │
│  ┌──────────┐      ┌──────────┐      ┌──────────┐              │
│  │ Service  │─────▶│  Kafka   │─────▶│ Service  │              │
│  │    A     │      │          │      │    B     │              │
│  └──────────┘      └──────────┘      └──────────┘              │
│       │                                    │                    │
│       ▼                                    ▼                    │
│  ┌──────────┐                        ┌──────────┐              │
│  │   DB     │                        │  Redis   │              │
│  │ (MySQL)  │                        │          │              │
│  └──────────┘                        └──────────┘              │
│                                                                 │
│  测试场景：                                                     │
│  1. Service A 发送事件 → Kafka → Service B 处理                │
│  2. Service A 写入 DB → 发布变更事件 → Service B 同步          │
│  3. 端到端业务流程测试                                         │
│  4. 异常场景（网络分区、消息丢失、重复消费）                   │
└─────────────────────────────────────────────────────────────────┘
```

### 3.3 测试层次划分

| 测试层次 | 描述 | 覆盖范围 | 执行频率 |
|----------|------|----------|----------|
| **单元测试** | 测试单个组件的内部逻辑 | Serializer, Handler, Mapper | 每次提交 |
| **组件测试** | 测试 Producer/Consumer 组件 | 消息发送、消费、重试逻辑 | 每次提交 |
| **集成测试** | 测试服务间通过 Kafka 的协作 | 端到端消息流转 | 每日构建 |
| **契约测试** | 验证消息格式的兼容性 | Schema 版本兼容 | 每次变更 |
| **性能测试** | 测试吞吐量和延迟 | 消息处理能力 | 每周 |

## 4. 技术约束

### 4.1 技术栈要求

| 组件 | 推荐版本 | 说明 |
|------|----------|------|
| Java | 17+ | LTS 版本，支持最新特性 |
| Spring Boot | 3.2+ | 微服务框架 |
| Apache Kafka | 3.6+ | 消息中间件 |
| Testcontainers | 1.19+ | 容器化测试框架 |
| JUnit | 5.10+ | 单元测试框架 |
| Docker | 24+ | 容器运行时 |

### 4.2 环境要求

- **开发环境**: Docker Desktop 或兼容的容器运行时
- **CI 环境**: 支持 Docker-in-Docker 或 rootless 容器
- **内存要求**: 最少 4GB 可用内存用于测试容器

## 5. 风险分析

| 风险项 | 影响程度 | 发生概率 | 缓解措施 |
|--------|----------|----------|----------|
| 容器启动时间过长 | 中 | 中 | 使用容器复用、预拉取镜像 |
| 测试环境资源不足 | 高 | 低 | 限制并行度、资源监控 |
| 网络不稳定导致测试失败 | 中 | 低 | 重试机制、超时配置 |
| Kafka 版本兼容性问题 | 中 | 低 | 版本锁定、兼容性测试 |
| CI 环境 Docker 权限问题 | 高 | 中 | 使用专用测试账户、权限配置文档 |
